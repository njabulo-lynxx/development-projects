# Development Projects

A personal repository dedicated to experimenting, learning, and developing my programming skills through hands-on projects.

This repository serves as a workspace for building small applications, exploring game development, testing programming concepts, and turning ideas into working prototypes.

## Purpose

The primary purpose of this repository is **learning through experimentation**.

Projects do not necessarily need to be polished, complete, or production-ready. Some exist simply to explore an idea, understand a concept, or figure out how something works.

This repository provides a space to:

- Experiment with programming concepts.
- Explore new technologies, frameworks, and tools.
- Practise and strengthen existing skills.
- Develop small projects and proof-of-concepts.
- Test ideas before developing them further.
- Experiment, troubleshoot, and learn from mistakes.
- Track progress through practical development.

## Project Structure

Projects are organised into three main categories:

### Games
Game development projects, prototypes, gameplay mechanics, and interactive experiences.

### Apps
Websites, web applications, utilities, and other application development projects.

### Experiments
Smaller programming exercises, debugging experiments, algorithm testing, and explorations of individual concepts.

Each category contains its own projects and experiments, organised into separate directories where appropriate.

## Project Quality

Not everything in this repository is intended to be professional or production-ready.

Code and projects may be:

- Experimental or incomplete.
- Unpolished or inefficient.
- Poorly structured.
- Heavily commented for learning purposes.
- Under development or temporarily abandoned.

And that's okay.

This repository represents the **learning process**, not necessarily the finished product.

## From Experiment to Project

Some ideas may eventually grow beyond their original experimental purpose.

When a project reaches a stage where it warrants further development, it may be moved into its own independent repository.

This allows it to receive dedicated documentation, a proper project structure, and continued development without being tied to the experimental environment.

The goal is to provide a starting point for ideas that may eventually become standalone projects.

## Learning Philosophy

> Build it. Break it. Understand why it broke. Fix it. Build something better.

I believe in learning through experimentation rather than trying to make everything perfect from the beginning.

Some experiments will be useful.

Some will be terrible.

Some will probably make future me question the decisions of past me.

All of them contribute to the learning process.
